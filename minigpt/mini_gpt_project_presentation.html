Slide 03 • Subword Tokenization

From Raw Bytes to Production BPE Tokenizers

Comparison of our three progressive tokenizer implementations across tokenizer1.py and tokenizer2.py:

1. CharTokenizer

Maps each Unicode character directly via ord(ch) and chr(t).

  • 'hello' → 5 tokens
  • 'Hello, world!' → 13 tokens
  • Zero compression (1 char = 1 token), resulting in long sequences.

2. Byte-Level BPE (tokenizer1)

Starts with 256 UTF-8 base bytes and iteratively merges top adjacent pairs.

  • Vocab Size: 306 (256 base + 50 merges)
  • 'The cat sat on the mat.': 23 bytes → 7 tokens (0.30 ratio)
  • Avg tokens/word across test set: 3.21

3. Production BPE (tokenizer2)

Adds Unicode NFKC normalization, GPT-2 regex pre-tokenization, and control tokens.

  • Vocab Size: 310 (256 + 50 merges + 4 specials)
  • Special IDs: <|begin|>=306, <|end|>=307, <|user|>=308, <|assistant|>=309
  • 'The quick brown fox.' → 5 tokens (0.25 ratio)

Filtering & MinHash LSH Algorithms

  • Unicode-Safe Cleaning: Regex removal of HTML tags (<[^>]+>), URLs, and extra whitespace while preserving Persian UTF-8 characters.
  • Quality Heuristics: Filters out short/noisy comments (retaining 15,721 high-signal clinical reviews), spam ratios, and excessive special characters.
  • MinHash + LSH Deduplication: Extracts 5-word shingles, computes 128-permutation MinHash signatures (prime $2^{61}-1$), partitions into 16 LSH bands, and removes pairs with Jaccard similarity $\ge 0.80$.

Slide 05 • Model Architecture

From-Scratch PyTorch Pre-Norm Transformer (`MiniGPT`)

Every neural network primitive in mini_gpt_torch.py was mathematically constructed using fundamental PyTorch tensor operations:

1. Joint Embedding & Pre-LayerNorm

  • Token + Positional Embeddings: Initialized with $\mathcal{N}(0, 0.02^2)$, summing token lookups $(B, T, D)$ with broadcast positional indices $0 \dots T-1$.
  • Custom LayerNorm: Computes biased mean $\mu$ and variance $\sigma^2$ along the last axis:
    y = gamma * (x - mean) / sqrt(var + 1e-5) + beta
  • Pre-LN Residual Stream: Normalizes before Attention and FFN sub-layers (x = x + attn(ln1(x))) for smooth gradient flow without warm-up instability.

2. Causal Multi-Head Attention & Loss

  • Scaled Dot-Product Attention: Projects $Q, K, V \in \mathbb{R}^{B imes H imes T imes d_k}$ without bias, scaling scores by $1/\sqrt{d_k}$.
  • Dtype-Safe Causal Mask: Upper-triangular mask filled with torch.finfo(dtype).min so future tokens receive zero probability in both float32 and float64.
  • Manual Log-Sum-Exp Cross-Entropy: Subtracts $\max( ext{logits})$ before exponentiation to guarantee zero NaN/Inf overflow during training.
  • Weight Tying: Output logits reuse embedding.token_embed.weight.T.

Slide 10 • Future Roadmap

How to Improve the Model & Next Engineering Steps

To evolve this prototype into a high-fluency Persian medical language model, we recommend six concrete upgrades:

1. Longer Pipeline Training (2,000+ Steps)

Increase pipeline training from 400 steps (~1 epoch) to 2,000–3,000 steps (~6–8 epochs) with lr=5e-4 so cross-entropy loss drops from 3.81 down below 1.80 for coherent Persian sentences.

2. Larger Persian BPE Vocabulary

Expand BPE merges from 150 to 4,000–8,000 subword tokens using ProductionTokenizer (with regex installed for Unicode \p{L}+ support) so full medical words map to single tokens.

3. Context & Architecture Scaling

Increase seq_len from 64 to 256–512 tokens, scale embed_dim to 256–512, and replace standard ReLU in FeedForward with GELU or SwiGLU and RoPE (Rotary Position Embeddings).

4. Cosine LR Schedule & Clipping

Add linear warmup (first 100 steps) followed by Cosine Annealing LR decay and gradient norm clipping (max_norm=1.0) to stabilize updates and prevent loss spikes.

5. Top-k / Top-p (Nucleus) Sampling

Upgrade generate() with Top-k ($k=40$) and Top-p ($p=0.90$) filtering plus a repetition penalty to prevent subword merging artifacts like ریزرویزیمماییشنوق.

6. KV-Cache & Full 334K Dataset

Implement Key-Value caching for $\mathcal{O}(N)$ autoregressive generation and train over all 334,000 doctor comments using GPU mixed-precision (bfloat16/float16).
